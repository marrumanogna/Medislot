# Data model

Generated by `scripts/generate_docs.py`. System of record is **RDS MySQL**; fast-changing state (seats, offers, tokens, dispatch log) lives in **DynamoDB**.

## RDS MySQL (`scehma/schema.sql`)

### `users`
Login accounts: e-mail, password hash, role (PATIENT / DOCTOR).

Columns: `user_id`, `first_name`, `last_name`, `email`, `password_hash`, `role`, `is_active`, `created_at`, `updated_at`, `ON`

### `doctor_profiles`
Doctor profile: name, specialisation, experience, languages, photo, timezone.

Columns: `user_id`, `full_name`, `licence_number`, `specialization`, `qualifications`, `experience_years`, `hospital_name`, `hospital_address`, `hospital_city`, `languages_spoken`, `bio`, `consultation_fee`, `photo_key`, `timezone`, `verification_status`, `verified_at`, `verified_by`, `rejection_reason`, `licence_document_key`, `created_at`, `updated_at`, `ON`, `name_last_word`, `GENERATED`, `ON`

### `patients`
Patient profile linked to a user.

Columns: `patient_id`, `user_id`, `full_name`, `date_of_birth`, `gender`, `phone`, `address`, `city`, `emergency_contact`, `created_at`, `updated_at`, `ON`, `ON`

### `consultation_catalogue`
Catalogue of consultation types a doctor can offer (name, duration).

Columns: `consultation_type_id`, `name`, `duration_minutes`, `is_active`, `capacity`, `created_at`, `updated_at`, `ON`

### `doctor_consultation_fees`
Which consultation types a doctor offers and the fee for each.

Columns: `id`, `doctor_id`, `consultation_type_id`, `fee`, `is_active`, `capacity`, `created_at`, `updated_at`, `ON`, `ON`, `REFERENCES`

### `availability_patterns`
Weekly working hours per doctor (day, start, end, active).

Columns: `pattern_id`, `doctor_id`, `day_of_week`, `start_time`, `end_time`, `timezone`, `is_active`, `created_at`, `updated_at`, `ON`, `ON`

### `doctor_blackout_dates`
Days a doctor is unavailable; blocked while patients are booked.

Columns: `blackout_id`, `doctor_id`, `blackout_date`, `reason`, `created_at`, `ON`

### `appointment_slots`
Bookable time slots generated from the availability patterns (DRAFT, AVAILABLE, BOOKED, BLOCKED).

Columns: `slot_id`, `doctor_id`, `consultation_type_id`, `slot_start`, `slot_end`, `display_order`, `status`, `NOT`, `created_at`, `updated_at`, `ON`, `REFERENCES`, `ON`, `REFERENCES`

### `specialization_options`
Lookup list for doctor search filters.

Columns: `specialization`, `sort_order`

### `experience_options`
Lookup list for doctor search filters.

Columns: `experience_years`

### `qualification_options`
Lookup list for doctor search filters.

Columns: `qualification`, `sort_order`

### `language_options`
Lookup list for doctor search filters.

Columns: `language`, `sort_order`

### `schema_migrations`
Which database migrations have been applied.

Columns: `migration_id`, `applied_at`

### `appointments`
A patient's booking: status CONFIRMED, COMPLETED, NO_SHOW or CANCELLED_*, reschedule count.

Columns: `appointment_id`, `slot_id`, `doctor_id`, `patient_id`, `consultation_type_id`, `slot_start`, `slot_end`, `fee`, `status`, `NOT`, `active_slot_id`, `idempotency_key`, `booked_at`, `cancelled_at`, `cancel_reason`, `reschedule_count`

### `refund_ledger`
One refund row per cancelled or no-show appointment (tier, percent, amount).

Columns: `refund_id`, `appointment_id`, `patient_id`, `fee`, `amount`, `refund_percent`, `tier`, `reason`, `created_at`

## DynamoDB (`cloudformation/data-stack.yaml`)

| Table | Key | TTL | Purpose |
|---|---|---|---|
| Slots | slot_id (HASH) | - | Seat counters per slot; optimistic concurrency prevents double booking. |
| Idempotency | idempotency_key (HASH) | expires_at | Remembers Idempotency-Key results so retries are safe (expires by TTL). |
| AuthTokens | token_key (HASH) + token_type (RANGE) | expires_at | Refresh tokens (expire by TTL). |
| Waitlist | slot_id (HASH) + waitlist_entry (RANGE) | - | Patients waiting for a full slot, first come first served (per-patient cap read from SSM `waitlist/max-per-patient`). |
| HoldOffers | slot_id (HASH) + offer_id (RANGE) | expires_at | Seat held for the next waitlisted patient; only one live offer per seat (expires by TTL). |
| NotificationLog | dispatch_key (HASH) | expires_at | Dispatch log: one conditional write per notification gives exactly-once delivery. |
